Installation & compatibility notes

Install AutoHotkey v2 on the Windows computer. Run the downloaded script on that computer, select Windows shortcut bridge, and generate a barcode containing one shortcut token only, e.g. {WIN+E}. Scanning sends AZX_WIN_E, which the script maps to Win+E. The scanner must act as a keyboard and should not append unwanted Enter/Tab. This is not necessary for normal text barcodes. Some protected system shortcuts such as Ctrl+Alt+Delete cannot be simulated by a normal program.

Some scanners can emit keys directly after proprietary programming. The exact supported functions depend on model, firmware, and keyboard mode. A laser-only 1D scanner cannot read QR codes; use an imaging 2D scanner.

Format and scanner guide

Code 128 is an excellent choice for short ASCII text and controls. QR, Data Matrix, Aztec and PDF417 hold longer content, but require a scanner that supports that symbology. Retail formats such as UPC/EAN require specific numeric lengths and checksums.

Enter vs Tab vs Line Feed — what's different?

Enter is usually CR (ASCII 13). A line feed is LF (ASCII 10). CRLF is both. Tab is ASCII 9. Scanner keyboards may use firmware-dependent mappings, so always confirm in the tester. Windows, Alt, Shift and Ctrl modifiers aren't standalone ASCII characters.

What about Ctrl, Alt, Windows and F-keys?

Those are key events, not portable text payloads. The Windows bridge maps printed trigger strings to them on a Windows PC. Some scanners also have a built-in Function Key Mapping feature or configurable prefix/suffix; consult its programming guide.

Why does my scanner ignore a code?

It might be a 1D-only laser scanner attempting QR, a barcode that's too dense, an unsupported format, missing quiet zone, excessive data, or a mismatched keyboard setting. Start with a short Code 128 test at full screen and high contrast.
